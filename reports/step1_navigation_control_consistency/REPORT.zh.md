# 导航与控制的几何语义

开发版本 `ba9bd191` 保留完整线段判定，不把它当作已验收的稳定执行。63 任务的对照基线是 `b6c9e0df` 的 `execution_progress`：60 成功、3 次恢复耗尽。原九案例和 seed22 在不同版本下的时间分开记录，不把 36.2 s、33.7 s 与 `b6c9e0df` 的 28.1 s、26.3 s 写成同一次基线。

物理自由空间是房间内缩减去人员占据缓冲。保守自由空间再经过 `simplify(0.10)` 和向外 `buffer(0.11)`。0.11 m 是规划裕度，本轮没有缩小它。其他 Guide 只在已分配路径的重算里作为临时障碍。初始全配对可见图不含其他 Guide。

## 1. 完整线段判定

轴对齐矩形上的期望穿透由线段与矩形的闭式裁剪给出，不调用被测函数，也不用更密采样充当证明。

| 线段 | 精确穿透 | 完整判定 |
|---|---:|---|
| 穿过矩形中部的水平弦 | 0.5 m | 拒绝 |
| 落在矩形边上的线段 | 0 | 接受 |
| 端点深入 1e-9 m 后离开 | ≤ 1e-7 m | 接受 |
| 端点深入 1e-6 m 后离开 | > 1e-7 m | 拒绝 |

递归在单边覆盖或 1-Lipschitz 上界成立时停止。超过 8192 次对分会拒绝并留下见证，不把未确定的线段当成合法。这次宽 U 图上没有走到该上限。

可见图边仍用 `free.covers`。seed30 Equal Arc 的障碍顶点对里，严格图没有收录、而完整判定会接受的边是 0 条。被拒绝的是真正穿入障碍的弦。没有发现“构图接受、完整判定拒绝”的障碍—障碍边。

## 2. 匹配失败的来源

诊断帧是保存轨迹上的第一次重指派失败，没有重做目标。

seed30 Equal Arc，22.8 s，预算已用 1 次。seed26 Equal Arc，23.7 s，同样是第一次恢复之后。两帧都是 19 名 Guide、19 个目标，自由空间和保守障碍都是单个多边形。

静态域路径矩阵：

| 类别 | seed30 | seed26 |
|---|---:|---:|
| 已找到路径 | 342 | 342 |
| 起点未进入查询 | 19（全部属于 Guide 9） | 19（全部属于 Guide 9） |
| 目标端点无效 | 0 | 0 |
| 静态分量不同 | 0 | 0 |
| 搜索完成但无路径 | 0 | 0 |

Guide 9 到自由边界的距离是 0，`free.covers` 为假，到保守障碍边界约 \(10^{-17}\) m。它在物理自由空间内。旧的边界节点在“引导与边界样本重合”时直接返回空，于是这一行没有查询。19 个目标都能从其余 18 名 Guide 到达，但 18 个起点不能覆盖 19 个目标，匈牙利算法只能把其中一个目标配到缺失边上。该结论只针对这张有限图。原指派的其余 18 条边都有静态路径。

第一次恢复发生在临时域：当前目标被另一名 Guide 占据。那次失败不是静态不可达。重指派使用的是不含其他 Guide 的静态域。

修复后，同一帧的 `navigate_and_assign` 装上原指派。投影质量与成对方法在 seed30 的 21.3 s 还遇到第二处：规划节点与真实位置差约 \(4\times 10^{-15}\) m，安装检查用数组精确相等，于是报 `invalid_candidate_path`。目标端点本来就用 1e-7 m。起点现在用同一个容差，并且只要规划节点与真实位置不同，路径就从真实位置起笔。

## 3. 转角停滞在哪一层

匹配能够安装之后，停滞仍在。仅顶点版本的宽 U seed30 Equal Arc，第 240 帧：

- 名义速度 0.061 m/s，指向已安装顶点。
- 只有这一名 Guide 时，过滤速度仍是 0.061 m/s，规划边界半平面的松弛约 \(10^{-9}\) m/s，一步可以前进。
- 保留全部 Guide 时，过滤速度约 \(10^{-8}\) m/s。活跃约束是规划边界，以及 Guide 4 与 Guide 5 的间距；后者的界约是 0，因为中心距已经贴着 0.75 m。

所以路径允许的边界顶点，在单 Guide 的局部模型里可以离开；把它停住的是相邻 Guide 的间距约束，不是把自由空间边界线性化之后单独封死。有限的单方向试验给出了单 Guide 的可行速度，没有证明联合速度不存在别的方向。本轮没有把这个观察做成新的推开或让行。

## 4. 实施的修复

只改共享的端点连接，没有第二套控制器，也没有退回五点采样。

- 引导与边界样本重合时，沿离开障碍、进入自由空间的方向移动既有的 \(10^{-8}\) m，得到可见图节点。执行状态不动。
- 规划节点与真实位置不完全相同时，路径前缀保留真实位置。
- 安装时起点和终点都用原 1e-7 m 容差。

0.11 m 规划裕度、0.75 m 中心距、0.55 m 墙距、1 m/s、400 步和 3 次恢复预算都没有改。

## 5. 回归

小回归先跑了细长 seed30 成对方法、宽 U seed30 三方法、宽 U seed26 Equal Arc 和 v1 seed22。细长仍是 19.1 s 成功。三个 seed30 都从匹配失败变为恢复耗尽。seed26 与 seed22 也是耗尽，没有新的未解释终止类型。随后跑了 73 次执行。

相对 `b6c9e0df` 的 `execution_progress`：

| 口径 | 结果 |
|---|---|
| 90 行 | 48 成功，27 个输入失败保留，15 次恢复耗尽 |
| 63 个有效任务 | 48/63 |
| 匹配失败 | 0 |
| 原 60 个成功中退化 | 12，全部是宽 U，现在都是耗尽 |
| 逐坐标未变的成功 | 39 |

| 独立复判不一致 | 0 |
| 目标坐标变化 | 0 |

相对 `ba9bd191` 的 6 次匹配失败，现在都变成耗尽。成功数没有增加。

原九案例的保存源是场景闭环修复轨迹。细长和窄 U 六条仍与该源逐坐标成功。宽 U 三条这次是 31.1 s 耗尽。`b6c9e0df` 对同一保存源的重放是 28.1 s 成功、2 次恢复；`ba9bd191` 已是 31.1 s 耗尽。seed22 的保存源是 33.7 s 成功、2 次恢复；`b6c9e0df` 重放是 26.3 s 成功、0 次恢复；`ba9bd191` 和本轮都是 29.0 s 耗尽、3 次恢复。

安全判据在失败轨迹上仍可通过。约 \(10^{-8}\) m 的 Guide 净裕量只表示间距约束接近活跃。
