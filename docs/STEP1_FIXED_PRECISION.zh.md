# 固定精度标量契约与条件轴框闭包

本轮补充GEOS 3.14.1的精度构造、点量化及零平移缩放量化契约。
这些契约不依赖理想多边形凸包严格包含，也不假定DD求交正确舍入。
它们尚未覆盖整个BufferOp／SnapRoundingNoder，默认服务门控继续不可认证／回退，F4未完成。

## 模型与源码前提

固定版本源码及原版权／COPYING封存在本批`upstream_sources/`，本项目GEOS及C API DLL的hash另记入manifest。
源码依据为[PrecisionModel.cpp](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/geom/PrecisionModel.cpp)、
[math.cpp](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/util/math.cpp)、
[ScaledNoder.cpp](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/noding/ScaledNoder.cpp)和
[BufferOp.cpp](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/operation/buffer/BufferOp.cpp)。

`multigroup/precision_enclosure.py`使用精确有理值表达已声明的binary64运算，
RN为基本运算的最近舍入，u=2^-53，η=2^-1075；中间运算溢出拒绝。
只覆盖FLOATING及正有限固定scale，不覆盖FLOATING_SINGLE、负scale构造入口或非零平移ScaledNoder。
有理模型将+0与−0视作同一个XY值；实际原生复判另按float.hex保留并比较零符号。

请求网格g>0经RN(1/g)构造scale，随后库按其已有严格1e−5参数归一化接近整数的scale或内部gridSize。
这是上游库的参数，不是本项目新增验收容差。
设归一化后scale为S、内部gridSize字段为G：

- G>1：Q(x)=RN(J(RN(x/G))·G)。
- 否则S>0：Q(x)=RN(J(RN(x·S))/S)。
- FLOATING：Q(x)=x。

J对二进制输入就近取整数，中点朝+∞；以精确floor(x+1/2)表达。
不能在binary64中先算x+0.5再floor，例如略低于0.5的相邻浮点数会被该替代错误推过中点。
库实现使用modf分支，独立复判按这些分支重现。

`serial.actual_grid_fraction`保存的是内部字段G；不能笼统解释为每条路径的有效量化步长。
例如请求2.00000001时G=2，但get_precision报告RN(1/S)，二者不同；
请求1.00000001时G可归一化为1，而S仍小于1，实际进入乘scale分支。

## 外包推导与闭包后置条件

正乘除、RN和J单调。在有理区间中取最小／最大可表示binary64输入，分别应用Q，
即可包围区间内所有可表示输入；区间无可表示输入或不能建立有限运算域时拒绝。
若|x|≤M，则量化位移可用以下精确有理界：

- G>1：E₁=uM+ηG+G/2。
- 其余固定模型：E₁=uM+η/S+1/(2S)。
- D=E₁+u(M+E₁)+η。

前两式包括第一次乘／除舍入及整数化，最后一式计入恢复坐标时的舍入。
不能直接用请求网格g/2代替这个界。
保存的一个具体反例为g=1/10000.000009（按binary64计算）、x=0.00005：
归一化S=10000，原生输出0.0001，位移比请求g/2多
1660207/36893488147419103232。
其他条件下的首个半网格反例也可能由运算舍入产生，不能全部归因于构造归一化。

`invariant_axis_box`把输入轴框与各声明模型的像取包络，最多迭代8次；
只有直接验证所有声明映射把当前框映回自身时才返回。
另可同时加入零平移ScaledNoder标量映射RN(J(RN(x·S))/S)，
即使点量化走G>1分支也单独检查该映射。
因此，在这些映射及已经证明保持轴框的操作间任意次组合，返回坐标仍在框内。
这是一条条件闭包定理；没有据此假定未审查的所有GEOS操作均保持该框。

## 开发与复判证据

10种模型×3种端点坐标框宽度（0、0.001、0.12m）共30条件。
每条件复用父批全部167个原生点输出（含重复），再加18个中点／相邻浮点夹具；
185条输入各调用中心、框内最小及最大可表示坐标，共555次点量化。
这些端点坐标框不是人员观测误差传播结果。

| 项目 | 数量／结果 |
|---|---:|
| 完成条件 | 30/30 |
| 实际点量化调用 | 16650 |
| 坐标范围／位移界检查 | 33300 |
| 原生固定精度线段叠加调用 | 210 |
| 空叠加输出 | 57 |
| 建立并直接复核量化闭包的轴框 | 210 |
| 仅诊断的请求半网格反例条件 | 17 |
| 实际模型／范围／位移界违反及程序错误 | 0 |

叠加使用父批7个非零长度线段夹具，10模型×7夹具为70组唯一名义输入；
三档坐标框重复调用同一名义叠加，所以210次调用不是210个不同几何输入。
57个空输出对应19组唯一名义输入，不计为部署成功。
轴框迭代检查次数为1次149框、2次57框、3次4框，均在预定8次预算内。
零长度LineString按预定域排除，父批零长度Segment C API结果保留。

独立冻结复判再次实际运行16650次点量化与210次叠加，按hex比较全部输出；
按另一套普通float／modf表达式核对构造及量化，并直接检查保存框极值的闭包后置条件，
未以重跑同一个闭包迭代器代替后置条件验证。范围端点等于实际原生极值输入的输出，位移界公式另用有理数核对。
父批269次原生Segment调用也追加hex级复判，全部一致。
17个条件各只保存首个已知不成立的半请求网格界反例，不将它计作活动契约失败或独立科学样本。

本轮全量测试514 passed、1 skipped／63.18s；新增6项包含中点方向、构造字段差异、
无效半请求网格界、单调外包、闭包及实际Shapely精度结果。
测试通过不证明整个内核、无限时域稳定性或一般人员误差下服务保证。
