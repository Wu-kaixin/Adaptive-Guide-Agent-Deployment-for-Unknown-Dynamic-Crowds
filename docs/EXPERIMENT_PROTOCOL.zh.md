## 方法公平比较

`experiments/step1_fair_comparison.yaml` 规定场地、形状、规模、需求和资源。
任务生成时只替换 `controller.method`。同一单元的场景、人群参数、Guide 数量、边界、导航和安全阈值相同。
资源水平改变的是 Guide 数量，因此初态不同；方法对比必须留在同一资源水平内。
Guide 数量由生成多边形的外偏移周长和规划间隙预算算出，只作为实验预算，不保证成功。
协议固定为 `fixed_n`，数量等于该单元的 Guide 数，避免自适应搜索用更多 Guide 换成功率。

开发种子是 0、1、2、3、4。确认种子是 5–14。一般曲线诊断使用 seed 15–19，只旋转给定曲线的参数起点，协议是 `experiments/step1_general_curve_diagnostics.yaml`。正式种子 5000–5029 只由 `experiments/step1_projection_formal.yaml` 运行；开发和确认入口仍然拒绝它们。

曲线诊断给规划器一条标明来源的闭合曲线和常数弧长密度。它不从人员估计边界。纯规划任务不能标成部署成功；没有人员或环境时，路径和安全保持未评价。数量用 `ceil(L/H_p)` 和半圆弧弦长对应的余量档，不按某种方法是否成功改 N。

成对约束诊断是 `experiments/step1_curve_constraints.yaml`。它在上述六条曲线的十二个单元上比较 Equal Arc、`projected_mass`、只调相位和全部成对欧氏约束。规划间隙仍是 1.94 m，执行验收间隙仍是 2.0 m。求解预算在运行前固定。求解器成功标志不是独立验收，迭代耗尽也不是不可行证书。场景闭环是 `experiments/step1_scene_closure.yaml`：人员位置和半径进入凸包或圆盘并集，生成多边形不进入控制器。1.6 m 内缩只属于给定曲线的附着程序，不作为安全距离。这两份都是开发诊断，不是正式种子验证。

确认协议是 `experiments/step1_projection_confirmation.yaml`：同一场地、需求和冻结数量，方法只保留 Equal Arc、Mass CVT 和 `projected_mass`，种子是 5–14，共 540 个任务。数量沿用种子 0–4 上测得的圆形 14／17／20 和椭圆 16／18／22，不按新种子的曲线长度重选，也不按某种方法能否成功来改。新种子上的数量必要条件单独报告。配对差值的区间按种子整组重抽样，不把同一种子下的形状、需求和数量档当成独立重复。RA-ABDC 不重复运行。
正式协议使用同一套场景、热点、数量、优化预算和验收阈值，只把种子换成 5000–5029，共 1620 个任务。统计在看结果之前固定：10000 次种子整组重抽样，分析随机数种子 20261016。主指标是完整任务成功率、`projected_mass` 相对 Equal Arc 的原始需求规划代价，以及已执行方案的覆盖和安全验收。失败留在分母里。没有轨迹的时间、路径和实际代价不填零。代表案例取规划代价差的中位配对、最差配对，以及 Equal Arc 成功而 `projected_mass` 失败的全部单元。
完整因子表现有六种方法、4860 个任务。准备配置不等于已经得到比较结论。上一轮热点试点仍是 150 个任务。本轮消融是 `experiments/step1_projection_ablation.yaml`：圆形与椭圆、均匀／弱热点／强热点、按实现曲线选取的三档数量、Equal Arc／Mass CVT／`projected_mass`／RA-ABDC、seed 0–4，共 360 个任务。圆形数量是 14／17／20，椭圆是 16／18／22。弱热点乘数 2，强热点乘数 5，圆心规则和半径比例相同。违反必要数量下界的两个诊断任务单独存放，不进入这张表。跨形状热点用冻结需求的 Gaussian 超额，不用最近人员窗口。均匀需求的超额指标记为不适用。数值参照只比较目标位置，不进入这 360 个任务的执行统计。

失败标签不改变九类验收：

| 标签 | 含义 |
|---|---|
| `resource_shortfall` | `CAPACITY_SHORTFALL`，必要数量或指定数量超过可用 Guide |
| `planning_failure` | 边界、间隙、间距或路径在执行前没有可接受目标 |
| `execution_failure` | 已有目标之后的超时、恢复耗尽、安全拒绝或终端覆盖未通过 |
| `initialization_failure` | 人群或 Guide 初态无法建立 |
| `experiment_error` | 程序异常，单独记账 |

更细的阶段诊断写在 `stage_diagnosis`，也不改终止状态：

| 阶段 | 含义 |
|---|---|
| `certified_infeasible` | `N < ceil(L/H_p)` 或 `N > floor(L/d_min)`，这是不可行证书 |
| `no_plan_found` | 必要数量条件成立，有界搜索未找到可接受目标；不是“不存在可行方案”的证明 |
| `plan_found_assignment_failed` | 已有目标，可达指派失败 |
| `plan_found_execution_failed` | 指派完成后执行未通过独立验收 |

`high_demand_side` 的 20／24 Guide 诊断使用原配置。该配置的 demand 是逐人独立抽样，不是空间热点。空间热点由 `demand_region` 给出：固定圆心、半径、乘数和背景需求；生成一次后冻结。人员需求映射到部署曲线的唯一途径是 Gaussian 曲线密度（Mass CVT 用需求质量，Average CVT 用局部平均）。这仍然只是规划权重。
