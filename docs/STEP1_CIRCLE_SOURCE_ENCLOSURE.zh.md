# 人员位置框到初始圆盘源坐标

`multigroup/circle_source_enclosure.py`把[静态人员中心框](STEP1_STATIC_PERSON_ENCLOSURE.zh.md)
传播到圆弧源坐标的轴框，并另行对完整原生Point.buffer输出做有限传递检查。
这两项证据范围不同；默认门控保持回退，没有完成原参考服务保证或整个Step1闭环。

## 源表达式与数值条件

固定GEOS 3.14.1的[OffsetSegmentGenerator.cpp](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/operation/buffer/OffsetSegmentGenerator.cpp)
在圆弧生成时使用中心坐标加半径乘三角分量；圆首点和闭环复制也在同一范围内。
[Angle.h](https://raw.githubusercontent.com/libgeos/geos/3.14.1/include/geos/algorithm/Angle.h)
调用sin／cos并将接近0的结果置0。
本契约明确假设这些结果有限且位于[-1,1]，不假设三角函数正确舍入，也没有形式验证其运行库实现。
[OffsetSegmentString.h](https://raw.githubusercontent.com/libgeos/geos/3.14.1/include/geos/operation/buffer/OffsetSegmentString.h)
插入时调用makePrecise，随后可能删除冗余点或复制首点闭环。
本地封存这些源码及原版权／COPYING，共10文件；该类相关实现位于头文件，未以不存在的同名cpp补造源码。

设真实几何输入中心为binary64，允许中心框的最小／最大可表示坐标分别为a、b；
d是**实际传入原生buffer的binary64距离**。对任意有限t∈[-1,1]，d≥0：

- 分离运算RN(c+RN(d·t))位于[RN(a−d),RN(b+d)]。
- 融合运算RN(c+d·t)也在同一范围。

理由是binary64单调舍入把d·[-1,1]的乘积包含于[-d,d]，两端乘积本身可精确表示；
最终加法也单调。融合运算的精确乘积同样位于该区间。
因此无需经验pad，也无需以正确舍入的sin／cos为前提。
但不能漏掉最后的RN：例如1.0加二进制0.1后，实际输出1.1略大于两个输入的精确实数和。
本契约直接求最终舍入极值，没有将理想实数半径外扩当实现界。

指定精度模型时，再把上述框传入已声明的点量化映射；没有指定则为FLOATING源坐标。
冗余点删除、闭环复制和数学意义的直线弦均保持轴框。
后续binary64插值仍需独立的插值契约；结点、图构造、完整buffer和未知精度回退不会由这一步自动获证。
中间溢出、输入框没有可表示二进制中心或声明模型不足时拒绝。

## 实际半径的获得

初始原参考圆盘使用准确观测身体半径加原construction_margin。
分析器执行当前`geometry.outer_disk`的实际Python半径表达式，
仅在进程内短暂截获Point.buffer入口，记录传入距离；该阶段不调用原生几何。
截获结束后才运行真实Point.buffer，没有改默认函数、旧源码或其半径公式。
这避免用另一套secant近似悄悄替换原构造。

本批只有一种实际输入半径0.20500000000000002m，对应原生距离0.2052472292774305m，quad_segs=16。
20次半径表达式捕获是20个案例的重复，不是20种半径，也不是原生圆盘调用。
源公式适用的数值条件与这批有限半径覆盖分开解释；不能据此声称已测多身体尺寸或q32全部路径。
