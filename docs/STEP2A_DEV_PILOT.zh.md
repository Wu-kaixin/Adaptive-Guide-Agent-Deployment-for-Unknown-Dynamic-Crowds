# Step 2a 开发试点草案

本文件只定义以后最多 24 行的开发试点。本轮不抽种子、不生成人群、不运行。`experiments_open: false`，`run_in_this_round: false`。机器可读草案是 `configs/step2a/dev_pilot_draft.yaml`。

研究问题：在两群静态、总人数固定、共享同一套 Guide 和同一组 `curve_ceil` 下界时，`floor_then_size` 与一份事先写死的 `frozen_initial_split` 在预检和 `fixed_paths_no_recovery_v1` 执行上如何不同。这是开发数据，不是盲确认，也不比较算法优劣。

样本是一次人员抽取。两个策略共用这次抽取的人员、成员划分、曲线下界、Guide 身份和初态。24 行来自 2 种人数划分（12/12 与 8/16）、6 次抽取、2 个策略。种子命名空间是 `step2a-dev-pilot-20261023`，字面种子 100–105。开抽之前必须审计这些种子尚未用于本项目的其他协议。不得使用 5000–5029。

Guide 初态在看到任一策略结果和目标之前生成一次。`frozen_initial_split` 只按 Guide ID 排序后，在按字典序排列的群体之间交替分配。不能从 `floor_then_size` 的结果反推或改写这份映射。下界违约留在该行，不因此重抽。

边界是现有凸包，部署是 Equal Arc、相位 0，执行是无恢复的固定路径政策。分母是全部 24 行。系统成功必须群级和系统级同一终端窗口都通过，并且流程正常。只在实际运动子集上报告路程和保持，不能拿这个子集代替 24 行分母。

出现程序错误或工件哈希不一致就停止本批。不调参，不重抽，不挑成功的行重跑。
