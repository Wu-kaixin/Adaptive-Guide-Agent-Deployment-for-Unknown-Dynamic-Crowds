# 原参考包络的buffer实现前提审计与当前回退

## 结论与动作边界

当前GEOS的一般多边形圆角buffer不满足此前推导采用的通用内包含式

    A ⊕ B(r cos(π/64)) ⊆ buffer_q16(A,r)。

已保存一个有理数点分类确认的反例。这还不是当前全部人群参考管线的反例：
80个旧物理输入、640帧旧观测、2520个群占据边界的特定角点探针搜索没有找到同类管线反例。
有限未命中也不能完成对全部允许观测／真值的证明。

因此新活动代码的`build_support`将包络标为`UNPROVEN_GENERIC_BUFFER_BOUND`，
`certificate`对该构造返回`UNCERTIFIED / support_enclosure_transfer_unproven`，后续稳定更新使用贪心回退。
没有扩大几何容差，没有修改q16／q32点圆盘规则，没有改原安全、覆盖、服务或截止阈值。
数学上“给定正确支持域后的覆盖支配”仍是条件命题；不等于当前构造已经提供了正确支持域。
精确观测的独立有理积分原型不使用这一支持域假设，仍维持其原条件和限制。

全部旧研究快照和原结果不重写：已完成的轨迹／决策复判及真实服务检查仍是对应冻结版本的经验结果。
此前一般误差服务证书的普适实现论证需要补充；不能将旧路程收益沿用为这个已回退活动版本的性能。
这次修订不表示已观察到旧轨迹不安全、旧服务越界或原输入族支持域遗漏。

## 与本机版本一致的一手实现

本机为Shapely2.2.0、GEOS3.14.1。Shapely官方说明buffer输出多边形，圆弧由quad_segs参数控制近似段数。
见[Shapely buffer文档](https://shapely.readthedocs.io/en/stable/reference/shapely.buffer.html)。

GEOS3.14.1的圆角生成器用`int(totalAngle / filletAngleQuantum + 0.5)`决定段数，
再以总转角除以段数生成弦。因此小角圆角可能只有一条弦，其角跨度大于名义π/32。
该版本还存在最小顶点间距处理。
见[固定版本OffsetSegmentGenerator源码](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/operation/buffer/OffsetSegmentGenerator.cpp)。
环输入还会先按buffer距离的1/100简化部分浅凹结构，
见[固定版本OffsetCurveBuilder源码](https://raw.githubusercontent.com/libgeos/geos/3.14.1/src/operation/buffer/OffsetCurveBuilder.cpp)。
所以只换一个余弦常数，尚不足以证明完整实现、填孔和重采样的所有包络关系。

## 全精度反例

源多边形位于40×30m室内，关键顶点(20,10)，相邻方向的外转角为0.14628040793277478rad。
在半径1、q16下，该圆角只用1段，弦的径向距离0.9973264474458289，
小于所宣称内界半径0.9987954562051724。

测试点为(20.072933314981636, 9.004607416581472)。它到源顶点的平方距离为

    78921205957067801821457052869 / 79228162514264337593543950336

严格小于宣称半径平方

    20233576930657650115690985431681 / 20282409603651670423947251286016。

源顶点属于A，故该点属于宣称的A扩张集合；将保存buffer顶点全部视为二进制有理数后，
精确射线分类判定该点在实际buffer多边形外。GEOS自身也判定不覆盖，浮点测得外距0.0007345043796711271m。
这里有明确的弦近似几何原因和有理数内外证据，不用边界容差或“浮点误差”解释掉差异。
完整源／输出／点坐标保存于`buffer_bound_development_v1/generic_witness.npz`，版本与分数保存于同名JSON。

## 可继续利用的连续几何推导

在理想欧氏集合运算中，令C=(A⊕B_c)⊖B_c，r≥c，则

    C⊕B_c = A⊕B_c，
    C⊕B_r = (C⊕B_c)⊕B_(r−c) = A⊕B_r。

第一式一边由开运算反扩张性得到，另一边由A⊆C得到。
这是推导中的集合恒等式，不是已证明GEOS结果可以这样替换；实际仍有圆弧近似、输入简化、填孔和折线重采样。

Nayar的Theorem1对真实平行集给出上表面积／体积上界，二维为2/r；
见[Reverse isoperimetric inequalities for parallel sets](https://arxiv.org/abs/2102.03680)。
它不直接给出当前近似多边形的周长，更不提供未知原参考落在丢失／新增服务区的有符号需求质量界。
接下来须先补齐特殊输入族或保守替代构造的实现包含证明，再推进F4；不得把支持域面积当作沿曲线需求质量。

## 下一构造的证明任务：先分离外包与内排除

可以先研究仅外包的凸支撑构造，避免再次依赖失效的通用内半径。
以下是精确欧氏集合层的引理，尚未替代活动实现：令A为有界占据集合，H=conv(A)，c≥0。
对C=(A⊕B_c)⊖B_c，有C⊆H。证明：若x∈C，则对任意单位方向u，x+cu∈A⊕B_c，
故x·u+c≤h_A(u)+c，即x·u≤h_A(u)；对所有方向同时成立便有x∈H。
所以A∪C及填孔后的集合仍在H中，半径r的理想正偏置在H⊕B_r中；
从该凸集合中取边界结点并连接直线弦，也仍在同一凸集合内。

若每个真实输入构造多边形包含于以真实人员中心P_i为心、半径a_i的圆盘，
且观测Z_i满足‖P_i−Z_i‖≤ε，则上述理想原参考外包的支撑函数可取

    h(u) = max_i [u·Z_i + (a_i+ε)‖u‖] + r‖u‖。

对于有限方向，取对应闭半平面的交仍是外包；不能把方向间的边界连成内接多边形冒充外包。
该公式不排除内部区域，因此可能明显更宽；它本身不会给出未知原曲线质量界或保证非平凡保持收益。

下一轮按下列依赖顺序推进，而不在方法尚未成立时重开确认：

1. 将实际outer_disk的保存二进制顶点、人员位置误差与上式a_i对应，逐项处理构造pad及取整；
   随后的GEOS正／负buffer、简化、snap、交点及填孔必须有实现误差界或换成可核验的保守算法。
2. 单独核验有限方向半平面相交的数值外包；仅增加未证实的经验pad不能完成普适包含。
3. 在外包成立后才研究内排除；不恢复cos(π/64)的通用多边形内包含假设。
4. 再推进参考结点／弦及原线性需求的有符号质量界，并明确可观测条件如何排除已保存的13对坏世界。
5. 冻结可用新版本后，先在全部旧反例和开发输入上验证，再审计未暴露输入并开展独立确认。

本节是证明分解和候选公式，未新增运行证书、未解封默认门控、未改变原参考构造或验收条件。

## 后续实现修订：精确凸包不能直接套到保存插值输出

上述“连接凸集合内结点仍在凸集合内”引理成立，但保存的二进制插值结点不一定精确位于源线段。
旧观测已找到精确1/2^49方向支撑反例，完成按GEOS公式的逐位归因；v1按协议停止，未放行。
另行推导的binary64插值误差外包只修正这一层，v2有限16方向开发及10080阶段组全算术复判已完成、差异0。
详见[插值外包契约](STEP1_INTERPOLATION_ENCLOSURE.zh.md)。闭运算／偏置的普适实现界及一般需求质量界仍未完成。

后续全部凸包面法向诊断v3已找到实际源族的闭运算包含反例：8个复用输入在第一阶段即停止，569方向独立复判一致。
这是另一条实现前提的具体反驳，不是上述通用圆角内半径反例的实际族探针命中；二者不能混记。
一例可由负偏置线段精确相交后的坐标舍入逐位重现，仍不构成所有GEOS运算的误差上界；见[全凸包面审计](STEP1_CONVEX_FACET_AUDIT.zh.md)。
