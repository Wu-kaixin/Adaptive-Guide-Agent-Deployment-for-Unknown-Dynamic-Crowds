## 2. 第一阶段：建立真正可恢复的检查点

每个完整任务已有config、planning、metrics、state、trajectory及receipt，已完成工作并非只在内存中。
接下来先阻止新增任务派发，在明确的任务写入边界登记完成集合；保存以下内容：

1. manifest/seal、协议、原源码快照及运行修订的哈希。
2. 完整receipt列表及各文件校验；确认完成、失败、程序错误、未执行和写入未完成目录。
3. 在途单元与任务身份、进程PID及创建时间、当前调度版本、日志及恢复所需命令。
4. 暂停状态凭据与恢复规则。操作性暂停不得写成PATH_NOT_FOUND或科学失败。

原始结果目录保留，检查点索引另存；不需要把全部数据反复压缩复制。
若创建额外备份，先核验空间、路径及hash，保留冲突；不要以清理目录为恢复步骤。

当前进程中的长任务尚未具备任意中间点持久化。应区分：

- 有receipt的完整任务：已有可核验的磁盘结果。
- 没有receipt的在途任务：不能宣称已经持久保存全部计算状态。
- 操作系统挂起：可以暂存活进程内存、释放CPU给剖析，但不能抵御断电或进程丢失。

优先让接近结束的任务完成写入；长任务如需保留现场可受控挂起。
不要在没有可恢复中间状态时，为换源码而直接杀掉所有工作进程并声称没有损失。
同时要把监督进程的状态与暂停操作协调好，避免它把操作性暂停误报成实验异常。

**交付物：**暂停/检查点凭据、完整与未完成任务索引、核验结果、可复现的恢复入口。

## 3. 第二阶段：先测量成本，不预设瓶颈占比

已从代码确认的候选成本包括：

- `multigroup/execution.py::_graph`枚举图顶点两两连线，候选数随顶点数近似平方增长。
  串行移动时其余机器人仍是障碍，不同机器人/状态可能重新构造图。
- `navigation/paths.py::_shortest`连接起终点并执行Dijkstra；当前实现会继续处理队列而非在目标确定后立即结束。
- `multigroup/evaluation.py::motion_metrics`在所有完整运动区间计算机—人、机—机、机—墙距离。
  串行运动中大量机器人静止，但目前仍参与完整批量计算。
- 真值参考几何、需求密度及服务采样在多个共享输入的任务间有重复构造机会。
- 候选目录、快照压缩、receipt核验、调度/状态扫描也可能产生开销。

以上是代码事实及候选优化机会，**尚不是各项耗时百分比的实测结论**。

建立独立性能目录，使用固定的少量诊断案例，不写回原确认results：

| 案例 | 目的 |
|---|---|
| K1小规模完成案例 | 识别固定启动/文件开销及回归 |
| K5低、中、高供给 | 分离机器人数量与资源档位成本 |
| 圆、椭圆、凹、不规则的重案例 | 覆盖几何复杂度与长尾 |
| 两个既有几何失败见证 | 保持端点拒绝、断连结果与安全边界 |
| 相同完整动作输入的重复任务 | 测量可复用计算的真实命中率 |

首轮选约8–12个有明确选择规则的案例，不追求完整因子网格。
每例分开计时：输入与构造、候选、分配、图构建、最短路、运动生成、独立验收、写盘。
另记录每张图顶点/候选边/有效边、实际区间数、峰值内存、读写量及缓存命中率。
短诊断可设置独立墙钟预算；超出预算只标记PROFILE_INCOMPLETE，不改原科学截止或失败状态。
性能剖析自身有开销，最后收益须用关闭剖析器的运行测量。

**交付物：**按案例及组件的成本表、长尾列表、缓存可复用比例，以及优先优化顺序。

## 4. 第三阶段：先做结果等价的优化

先考虑以下候选，具体顺序由耗时数据决定：

1. **避免完全重复执行。**若观察几何、初态、完整有序目标、房间、全部执行配置及实现版本完全相同，
   可以研究复用已核验的Execution。各任务仍独立保存身份、分配结果、评价与receipt，不减少科学分母。
   目标顺序也进入键，因为Hungarian指派和破同分可能依赖顺序；仅比较预算或群数不足。
2. **复用不变参考。**观察侧缓存与验收真值缓存严格隔离。
   真实参考几何/需求采样只给独立验收器，键包含真实输入hash及相关构造/采样配置；不流入控制器。
3. **加速几何谓词与批处理。**评估预处理几何、批量整段谓词及减少Python对象构造。
   每次仍检查同一自由域和相同整段条件，特别检查近边界案例的谓词是否一致。
4. **图与搜索的安全复用/提前结束。**同一完整自由空间及同一节点/边顺序时才复用图。
   其他机器人位置、被规划机器人身份或障碍变化，必须使缓存失效或完整验证受影响边。
   可研究Dijkstra在目标出队后结束；要保留权重、队列与破同分规则。
   不同多边形部分只有在证实严格分离时才能作为拒绝依据，不能仅因MultiPolygon编号不同而拒绝。
5. **利用静止结构的验收优化。**静态人体不动，串行策略通常每区间仅一台机器人移动。
   可研究复用静止对距离或只更新变化对，但必须保持每个完整区间的最小净距和违反计数。
   原始完整轨迹及独立验收契约保留；不能跳帧代替优化。

缓存应有明确内存上限、不可变内容、版本键与失效规则。并行度以固定基准吞吐决定，
可比较8/16/24/32路；当前32路CPU100%不代表它在所有几何与内存条件下吞吐最高。
不直接把32路乘以多线程，也不先假设GPU能够加速当前几何工作。

**尚不进入纯提速的改动：**降低图分辨率、删掉可能必要的图边、减少相位或候选、减少科学采样、
改变指派/移动顺序、改变外接障碍或安全阈值。这些可能改变科学结果，另走新方法协议。

### 等价性与收益门槛

固定旧实现为基准，比较数量/相位/有序目标、指派、路径、完整位置/速度数组、
安全最小值、违反计数、到达、FULL_SUCCESS/PARTIAL_SERVICE/失败分类与共同参考服务。
纯缓存/复用尽量要求逻辑数组逐位一致；NPZ容器时间元数据不作为科学输出。
不能通过放宽容差或只比较均值使差异消失。若不能解释差异，停止将优化视为等价。

计时分别报告冷启动、冷缓存、热缓存与整体固定案例总耗时，不能只报告全命中时间。
可预设第一轮工程目标，例如固定重任务总耗时降低至少30%且正确性零差异；
30%是建议的开发取舍门槛，尚未测得，不能当作预期保证。
结果未达目标时，重新看成本表，避免无限制重构延误科研。

原封存快照不能原地编辑。新实现须单独版本和哈希；不能通过改verify或刷新旧锁让新代码冒充旧代码。
调度优化可在单独运行修订下继续调用原快照；若核心计算换实现，须明确等价性证据、
实际后端来源和每条新增记录版本。样例通过本身不是任意输入等价的证明。
若等价性不足，保留旧确认未完成状态，新实现另立协议，不静默拼接成同一冻结实现结果。

**交付物：**固定基准、等价性报告、非剖析计时、峰值资源、后端/运行版本及恢复决策。

**执行可行性：**对已保存PATH_NOT_FOUND建立完整原因账本，区分起点/终点占据、
解析中心距与外接表示、静止机器人的阻断、严格分离的自由分量、连通域内图问题及原因不明。

表示一致性与顺序/指派协调分别做单因素实验，所有方法共用同一执行器和预算。
失败修复属于方法更新，不混入纯速度优化的收益。

**真实服务关系：**固定现有3,200条规划动作进行机制审计，以seed2210为强制反例。
观察的本群指派服务与真实的全体机器人共同服务需统一评价对象；
人员误差上界不直接充当曲线/需求测度误差界。
从可证明子类建立观测可计算的L_k(Q)≤U_k(Q)≤H_k(Q)，只有

    H_k(Q_ret) - L_k(Q_greedy) ≤ Δ_true，对每个可对应群体成立

且安全准入通过时才保留。群身份、权重及测度对应必须满足条件；否则UNCERTIFIED并回退。
回退仅限制相对同一可用基线的额外损失，不代表绝对服务或路径可行。
计划目标的界也需要通过实际终态或跟踪误差界连接到交付服务。
若条件成立却被真值反驳，停止相应新证书批次并保留反例。

两条主线可以在保存的动作与几何上先推进；不以等完整确认为借口延迟机制分析。
但也不在原32路重批次外再叠加未经资源预算的大量运动任务。

K2/K5×凹形/椭圆，每配置先3–5个未用开发seed，比较贪心、观察保留、有证书保留。
